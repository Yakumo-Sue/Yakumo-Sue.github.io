3.11 函数递归：自己调用自己

阶乘定义：0! = 1，n! = n × (n - 1)!。

执行阶段 计算
调用 Factorial(3) 等待 3 × Factorial(2)
调用 Factorial(2) 等待 2 × Factorial(1)
到达终止条件 Factorial(1) 返回 1
返回上一层 Factorial(2) 返回 2
返回最外层 Factorial(3) 返回 6

递归需要两个条件：明确的终止条件，以及每次调用都更接近终止条件。缺少任意一个，都可能导致调用层数不断增长。

本例限制到 20，是因为 20! 仍能放入 long，21! 已不能。递归还需要调用栈空间；不要尝试通过普通 try-catch 把无限递归当成可恢复的流程。

阶乘也可以使用循环，时间均为 O(n)，但循环额外空间可为 O(1)，递归调用栈为 O(n)。递归的优势是表达分治结构，第五章排序中的归并与快速排序会用到它。

5.1 排序解决什么问题

排序是按照某个比较规则重新排列数据，例如分数从小到大、时间从早到晚、等级从高到低。

本章统一把 int[] 升序排列，输入 {5, 3, 8, 4, 2} 时输出 {2, 3, 4, 5, 8}。所有方法都把结果写回调用方传入的数组；其中一些方法仍会使用辅助数组，所以“修改传入数组”不等于“额外空间只有常数”。

本章代码分别放在源码包的 Shared/SortingAlgorithms.cs，类名为 CSharpBasics.SortingAlgorithms。代码是针对教学编写的实现，不是从下面的参考资料复制的语言版本。

5.2 时间复杂度、额外空间与稳定性

n 表示数据个数。复杂度描述输入规模增大时工作量或空间用量的增长，不是某台电脑上精确的毫秒数。

复杂度 直观含义 常见例子
O(1) 额外工作量不随 n 增长 按索引读取一个元素
O(log n) 规模反复减半 有序数组的二分查找
O(n) 大致遍历全部元素一次 查找最大值
O(n log n) 多层分治，每层处理约 n 个元素 归并排序
O(n²) 数量级接近双重遍历 选择排序

稳定排序指相同关键字的记录在排序后仍保持原相对顺序。

例如三条记录依次是 A:90、B:80、C:90，按分数升序稳定排序后是 B:80、A:90、C:90，A 仍然在 C 前面。单纯整数数组中的两个 90 看起来一样，但排序学生、装备等记录时，稳定性可能有实际意义。

“原地”通常关注是否只需很少的辅助存储；本章在空间复杂度中把递归调用栈算进去，避免把递归快速排序说成完全不需要额外空间。

5.4 冒泡排序：每一轮把较大值推到右边

相邻两个元素比较，前一个较大就交换。一轮结束，当前范围中的最大值已经在末尾，下一轮可以缩小范围。

阶段 数组状态
初始 5, 3, 8, 4, 2
第 1 轮后 3, 5, 4, 2, 8
第 2 轮后 3, 4, 2, 5, 8
第 3 轮后 3, 2, 4, 5, 8
第 4 轮后 2, 3, 4, 5, 8

changed 用于检测某一轮是否完全没有交换；没有交换就已经有序，可以提前结束。只在严格大于时交换，相等值不互相越过，因此本实现稳定。

最好时间 O(n)，平均与最坏时间 O(n²)，额外空间 O(1)。适合入门理解，不是大型数据排序的常规首选。

5.5 选择排序：选出最小值，放到前面

每轮从未排序区域找最小值，与区域开头交换。左侧已排序区域逐步扩大。

例如 {5, 3, 8, 4, 2} 第一轮找到 2，与 5 交换，得到 {2, 3, 8, 4, 5}。

即使输入原本有序，仍然需要扫描剩余范围找最小值，所以最好、平均、最坏时间均为 O(n²)；额外空间 O(1)。

本实现不稳定。例如 2A、2B、1，第一轮把 1 与 2A 交换后变成 1、2B、2A，两个相同关键字的顺序已经改变。

5.6 插入排序：把新元素插入已排序区域

从第二个元素开始，暂存当前值，把左侧比它大的元素依次右移，再把它放进空位。

data[j] > value 使用严格大于，不把相等值往右推，因此相等元素保持相对顺序。

输入已排序时，每轮很快停止，最好时间 O(n)；平均与最坏时间 O(n²)；额外空间 O(1)，稳定。小数组或接近有序的数据常适合它。游戏结束时排序少量骰子记录就采用这个方法。

5.7 希尔排序：先做远距离插入，再缩小间隔

普通插入排序一次只挪一格。希尔排序先把相隔 gap 的元素当成同一组做插入，之后逐步减小 gap，最后执行 gap = 1 的插入排序。

本实现使用 n/2、n/4、...、1 的折半增量。增量序列会显著影响性能，不能把其他序列的结论直接套过来。NIST：Shell sort

对本实现，已排序输入仍需执行多轮扫描，最好时间为 O(n log n)；最坏时间为 O(n²)。平均性能依赖增量和数据分布，本教程不把它固定写成某一个通用幂次。

额外空间 O(1)，不稳定：远距离移动可能让相等关键字互相越过。

5.8 归并排序：先分成小段，再合并有序段

把数组划成左右两半，分别递归排序，再用两个指针合并。递归终止于区间只有零个或一个元素。


flowchart TD
    A[一个待排序区间] --> B[左半区间递归排序]
    A --> C[右半区间递归排序]
    B --> D[合并两个有序区间]
    C --> D
    D --> E[写回当前区间]

两个当前元素相等时，data[i] <= data[j] 优先取左侧，保证稳定性。缓冲区在入口创建一次，被递归层共享，避免每个小区间都创建一份完整缓冲。

本实现没有“区间已经有序就跳过合并”的优化，因此最好、平均、最坏时间均为 O(n log n)。额外缓冲区 O(n)，递归栈 O(log n)，合计额外空间为 O(n)。稳定，代价是需要辅助存储。

5.9 快速排序：按基准分区，再处理左右两边

选择一个基准值，左指针寻找不小于基准的值，右指针寻找不大于基准的值，交换后继续向中间收缩。分区后递归处理两边。

这里取中间位置的值作为基准，不表示一定能得到最平均的分区。交换后同时执行 i++、j--，可保证遇到重复值时也继续推进。

最好时间 O(n log n)；在通常的随机输入假设下平均为 O(n log n)；分区持续不均衡时最坏为 O(n²)。递归栈平均 O(log n)，最坏 O(n)。本实现不稳定。

中间值选基准能避开一些朴素首元素基准的问题，但不是最坏情况保证。实际库实现常有更多保护措施，不应直接把教学版当成所有生产输入下的最优方案。

5.10 堆排序：用最大堆反复取出最大值

最大堆满足：父节点的值不小于子节点。它不是“每一层从左到右都有序”。

使用从零开始的数组表示完全二叉树时：

节点关系 数组索引
左孩子 2 * i + 1
右孩子 2 * i + 2
父节点，i 大于零时 (i - 1) / 2

先从最后一个非叶节点开始下沉，建立最大堆；然后交换堆顶与未排序区末尾，把堆范围缩小，并重新下沉堆顶。

count 表示当前堆的有效元素个数，不是最后一个下标。交换到末尾的最大值已经有序，下一次调整不能把它再纳入堆。

建堆为 O(n)，完整排序平均与最坏时间为 O(n log n)；当前下沉实现遇到全相等键时可以很快停止，最好可为 O(n)。额外空间 O(1)，不稳定。常见资料把堆排序统一概括为 O(n log n)，通常是在表达一般表现或统一上界。

5.11 计数排序：为每种取值统计位置

如果数据都处在较小整数范围内，可以为每个可能的值设置计数槽。使用最小值偏移，就可以支持负数。

例如 {-2, 1, -2, 0}，键偏移后对应槽 0、3、0、2。先计数，再做前缀累计，最后按位置输出。NIST：counting sort

本实现从后向前放置元素，采用稳定计数排序的步骤。对纯整数看不出相等元素的身份，但该放置顺序能够推广到带相同键的记录。

用 R = maximum - minimum + 1 表示值域大小，时间为 O(n + R)，额外空间为 O(n + R)。不能只写“计数排序始终是 O(n)”而忽略 R。

实现先以 long 计算范围，避免 int.MinValue 到 int.MaxValue 的差值溢出；并把计数槽数量限制为一百万。范围过大时主动抛出参数异常，而不尝试创建巨大的数组。

5.12 桶排序：按数值范围分组，桶内再排序

把值按范围分到若干桶，每个桶内部排序，再按桶序连接。这里用交错数组保存各桶，桶内使用前面的稳定插入排序。NIST：bucket sort

关键步骤：先统计每桶容量，再创建刚好足够的内层数组；按原始顺序装入桶；逐桶执行插入排序。

span 和映射乘法使用 long，因此可以处理整个 int 范围的数值，而不要求全部非负。桶数必须大于零，实际使用桶数不会超过元素数。

设 k 为桶数。均匀分布、各桶内部顺序一般的假设下，本实现的平均时间可写为 O(n + n²/k + k)；若 k 与 n 同阶，可以接近 O(n + k)。若默认只用 10 个桶，不能把大规模输入的平均表现无条件当作线性。最坏为 O(n² + k)，额外空间 O(n + k)。

由于分桶保留顺序、桶内插入排序稳定，且相等值映射到同一个桶，本实现稳定。

5.13 基数排序：逐位稳定排序

以十进制理解，可以先按个位排、再按十位排，并保证每一轮稳定。低位已经形成的相对顺序因此可以在更高位相同时保留。NIST：radix sort

本实现针对固定 32 位 int，每次处理 8 位，也就是以 256 为基数，固定执行四轮；每轮采用稳定计数分发。

unchecked((uint)value) ^ 0x80000000u 把有符号整数映射成适合无符号比较的键：

原整数 映射后的无符号键
int.MinValue 0
-1 2,147,483,647
0 2,147,483,648
int.MaxValue 4,294,967,295

这样负数会排在非负数之前，也能处理 int.MinValue，不用对它求无法用 int 表示的绝对值。

一般写法为 O(d(n + b))，其中 d 是位数轮次，b 是基数；本实现 d = 4、b = 256 固定，所以对固定宽度整数可概括为线性时间。额外空间 O(n + b)，稳定。

基数排序、计数排序使用了键域的信息，不属于只靠两两比较的通用比较排序，不能直接套用比较排序的同一理论下界。

6.5 固定地图如何生成

路线按以下顺序把坐标放进 path：

  1. 上边从左到右 15 格。
  2. 右边从上往下补 6 格，不重复右上角。

  4. 左边从下往上补 5 格，不重复左右角点。

总数为 15 + 6 + 14 + 5 = 40。相邻坐标之间再填入横线或竖线，最后把公共格 0 与 20 标记成安全起点。

6.6 一回合的核心：ref 与 out

核心方法形状为：

  • ref plane：修改调用方保存的结构体状态。
  • dice：本次骰子点数，是普通整数参数。
  • out message：无论本轮移动与否，都产生一条说明。
  • 返回 bool：这次是否改变了位置。

机库中没掷出 6 和超出终点，都会返回 false，但本回合的投骰次数与历史仍然要记录。没有移动不等于没有掷骰。

调用时使用 TryAdvance(ref planes[index], ...)，直接修改数组元素。写成 PlaneState copy = planes[index] 后只修改 copy，却不写回，就会丢失变化。

6.11 游玩步骤

  1. 打开终端，调整到至少 73 列 × 33 行，运行游戏。
  2. 在开始界面按 Enter，A 与 B 都在各自机库。
  3. 按空格掷骰。A 若不是 6，继续留在机库；之后电脑自动掷一次。
  4. 某方掷出 6 后，它会出现在自己的 a 或 b 起点，进度为 0。
  5. 后续空格让双方轮流按点数前进。下方记录会说明本轮动作。
  6. 落在对方所在普通格时，将其送回机库；安全起点同格不攻击。
  7. 接近 40 时，如果点数太大则原地不动；恰好到达的那方获胜。
  8. 查看结束界面的投骰与攻击统计，按 R 再玩，或 Enter 回菜单。

只需空格即可完成游戏，不用 WASD 直接移动棋子。这样移动距离由骰子和固定航线决定。

C# 高级

C# 学习系列： C# 入门 → C# 基础 → C# 进阶 → C# 高级

接续《C# 入门》《C# 基础》《C# 进阶》。目标：从“能写类”走向“能组织集合、行为和运行时信息”，最后完成分层控制台俄罗斯方块。

配套项目目标框架：.NET 10，语言版本固定为 C# 12，启用可空引用类型检查。本文主体不依赖 C# 13/14 新语法；新增泛型约束单独说明。代码片段分为方法体片段、类型声明、完整文件，片段不应全部粘进同一个 Main。完整可运行代码见配套源码。方法体示例按需引入 System、System.Collections、System.Collections.Generic、System.Reflection、System.Threading；特定示例另列 using。涉及前文类型的片段应放在同一项目中。

第一章：简单数据结构类

1.1 本质：容器、元素类型与访问规则

这些类位于 System.Collections，属于非泛型集合，元素以 object 接口形态暴露。存入 int 等值类型通常发生装箱，取出时需要正确拆箱；混合类型会把错误延后到运行时。新项目优先使用对应泛型集合，本章用于理解历史代码和容器行为。

类 抽象规则 典型用途 泛型替代
ArrayList 动态长度、按索引访问 旧代码异构列表 List
Stack 后进先出 LIFO 撤销、回溯 Stack
Queue 先进先出 FIFO 等待、任务排队 Queue
Hashtable 按键定位值 映射、查表 Dictionary<TKey,TValue>

“动态长度”指容器内部按需扩容，不代表数组本身能改变长度。Count 是元素数；Capacity 是部分容器已分配容量，两者不同。复杂度描述默认以元素数 n 计，哈希操作平均 O(1)、最坏 O(n)，不保证所有输入均常数时间。

1.2 ArrayList：声明、增删改查和遍历

底层采用动态数组思想。索引访问 O(1)，尾部 Add 摊还 O(1)，中间插入、删除要移动后续元素，为 O(n)。

索引必须满足 0 <= index < Count；Insert 可在 Count 位置插入。Remove(20) 与 RemoveAt(20) 含义不同。Sort() 要求元素可互相比较，混入字符串与整数可能失败。一般不要在 foreach 中增删原集合；可倒序 for 删除，或先记录要删除的元素。

1.3 Stack：后进先出

栈顶是唯一常规进出口。Push 压栈，Pop 弹出并删除，Peek 只看栈顶。底层通常采用可扩容数组；Push 摊还 O(1)，Peek/Pop O(1)，Contains O(n)。

空栈 Peek/Pop 抛 InvalidOperationException。非泛型 Stack 没有按索引修改或删除中间项的常规 API；如确有需要，应弹出、重建，或重新选择容器。不要把“增删改查”理解成每种容器都必须支持随机修改。

1.4 Queue：先进先出

队尾入队，队首出队，适合事件和任务排队。可用循环数组实现；Enqueue 摊还 O(1)，Dequeue/Peek O(1)，Contains O(n)。

空队列的 Peek/Dequeue 会抛异常。它不提供索引器，也不支持直接修改队中第 k 项。游戏中可把“方块落地事件”按顺序入队，交给统计线程消费。

1.5 Hashtable：键值映射

哈希函数把键映射到桶，再用相等比较区分冲突。键应保持哈希与相等语义稳定；把参与 GetHashCode 的字段改掉，可能导致键还在表中却查不到。键不可为 null，值可以为 null。

读取不存在的键返回 null，不能仅凭结果 null 区分“键不存在”与“值是 null”。遍历顺序不应作为业务契约。以上集合默认均不适合多线程并发读写，线程安全需另外设计。

第二章：泛型和约束

2.1 概念、分类、作用

泛型把具体类型推迟为类型参数，仍保留编译期类型检查。List<int> 只能接收 int，避免非泛型集合频繁装箱和强制转换；但泛型不保证绝对没有装箱，例如把 T 转成 object 时仍可能装箱。

使用：Box<int> box = new Box<int>(3);；Tools.Swap(ref x, ref y) 通常可推断 T，也可显式写 Tools.Swap<int>。泛型方法需要自己声明类型参数；一个普通方法位于泛型类里，不代表该方法自身也是泛型方法。除此之外还有泛型结构体和泛型委托，例如 Nullable<T> 与 Func<T,TResult>。

2.2 传统六种约束

没有约束时，编译器不能假设 T 有某个业务方法。约束写在声明后，用 where 描述调用者必须满足的条件。

约束 含义 可依赖的能力
where T : struct 非可空值类型 值类型语义；隐含 new()
where T : class 引用类型 引用语义；可空上下文中要求非可空
where T : new() 有 public 无参构造函数的非抽象类型 可以 new T()
where T : Base Base 或派生类型 可以使用 Base 的可访问成员
where T : IFoo 实现接口 可以调用接口成员；结构体也可满足
where T : U T 可赋给 U 的类型约束 描述两个类型参数之间关系

多个约束用逗号连接，多个参数分别写 where。主约束在前，接口居中，new() 通常最后。struct 与 class 不能组合，struct 不能再写 new()；基类约束不能与 class/struct 主约束同时使用。接口可有多个。约束不是运行时 if，也不能只靠约束差异区分两个签名相同的重载。

2.3 不止六种：补充与版本边界

传统六种是入门分类，并非现代 C# 完整清单。notnull 要求非可空类型（违反时通常产生可空分析警告）；unmanaged 要求不含托管引用的非可空值类型，不能与 struct/new() 组合；Enum、Delegate 可作为约束；default 用于重写或显式接口实现中的特定约束消歧。C# 13 还有 allows ref struct 反约束，本文 C# 12 项目不使用。查看官方“类型参数约束”文档时应留意语言版本。

约束应表达算法真正需要的能力。仅需比较时约束 IComparable，不必限制为某个具体业务类。

第三章：常见泛型数据结构类

3.1 List：动态数组

位于 System.Collections.Generic。逻辑上有序，重复元素合法；底层连续数组保存 T 的值，若 T 是引用类型，数组槽位保存对象引用。

Find 返回 default 可能与真实元素混淆，可用 FindIndex（未找到 -1）。Count 不是 Capacity，Clear 后容量通常保留。TrimExcess() 可请求压缩多余容量，但不应频繁调用。ToArray() 得到新的数组，元素仍是浅复制。

3.2 Dictionary<TKey,TValue>

泛型哈希表，键唯一。TKey 受 notnull 约束；使用字符串键时明确选择比较规则。

不存在的键使用索引器读取会抛 KeyNotFoundException，TryGetValue 更适合常见的查询失败。键比较由 IEqualityComparer 决定，Equals 相等的键必须返回相同哈希码，反过来不成立。不要用字典遍历顺序表达排名；排名先复制到 List 再排序。

3.3 顺序存储与链式存储

操作 List 带头尾指针的单向链表 LinkedList 双向链表
索引访问 O(1) O(n) 不提供索引器，定位 O(n)
尾部增加 摊还 O(1) O(1) O(1)
头部增加/删除 O(n) O(1) O(1)
已知位置插入 移动后续项 O(n) 已知前驱 O(1) 已知节点 O(1)

链表插入快的前提是已经定位到合适节点，按值找节点的成本不能忽略。逻辑相邻不代表内存相邻。

3.5 LinkedList：双向链表

系统类的节点为 LinkedListNode<T>，具有 Value、Previous、Next、List。拿到节点后能常数时间在前后插入或删除。它既不是 List 的子类，也没有 [index] 索引器。

RemoveFirst/RemoveLast 在空链表上抛异常。节点不能同时属于多个链表；删除后可将脱离的节点加入另一个链表。修改节点 Value 与改变链结构是不同操作；不要依赖不同集合对遍历期修改的差异，统一采用“先收集，再修改”的清晰策略。

第四章：委托和事件

4.1 委托的本质、声明与使用

委托是类型安全的方法调用对象。一个委托类型规定参数和返回值形状；一个委托实例持有目标对象与方法组成的调用列表。实例方法需要目标对象，静态方法通常不需要。声明类型、定义方法、创建实例、调用实例是四个步骤。

委托让调用者提供变化的行为，例如“按哪种规则排序”，而不是在算法中写死。委托本身是引用类型，赋值不等于执行方法。

4.2 多播机制

通常所说“多播系统”是委托的多播调用机制：用 += 组合，用 -= 移除一个匹配的订阅，调用时按列表顺序同步执行。

委托不可变，组合产生新的委托值。重复订阅会重复调用；移除通常移除最后一个匹配项。普通调用中某个处理器抛异常，后续处理器不会继续执行。非 void 多播委托只能直接得到最后一个处理器的返回值，需要收集所有结果时逐个遍历 GetInvocationList()。多播默认不产生多线程。

4.3 系统委托

类型 形状 例子
Action 无返回值 Action<string> 接收一个 string
Func 最后一个泛型参数是返回类型 Func<int,int,int> 两个 int 输入、一个 int 输出
Predicate T → bool List.Find/RemoveAll 的判断
Comparison (T,T) → int List.Sort 的比较
EventHandler (sender,args) → void 事件通知

这些已经够用时，不必为每个方法形状创建新委托。业务语义特别明确时，自定义委托仍有价值。

4.4 事件：限制外部调用权

事件基于委托提供订阅/取消订阅机制。外部代码只能 +=、-=，不能覆盖整个调用列表，也不能直接触发事件。发布者决定何时发生，订阅者决定怎样响应。

4.5 匿名函数和 lambda

匿名方法：Func<int,int> square = delegate(int x) { return x*x; };。Lambda 可用表达式体 x => x*x，或语句体 x => { return x*x; }。无参数写 () => ...，多个参数加括号。

第五章：List 排序

5.1 自带 Sort 与 Reverse

Sort() 按默认比较器原地升序排列，元素需支持默认比较。Reverse() 只反转当前顺序，并不负责把无序列表变成降序。Sort(index,count,comparer) 可排序局部区间。

比较函数结果只看符号：负数表示 a 在前，0 表示同序，正数表示 a 在后。不要写 a-b 比较所有整数，极值相减可能溢出。比较应自洽且具有传递性，不应依赖每次变化的随机值。

5.2 自定义类排序

有天然默认顺序时实现 IComparable<T>；同一对象有多种排序规则时，用 IComparer<T> 或 Comparison。

List<T>.Sort 是不稳定排序，不承诺同分对象仍保持原先相对顺序。需要稳定性时可使用 LINQ OrderBy/ThenBy 后 ToList()（需要 System.Linq），或显式把原始索引作为最终比较条件。游戏的方块统计先按次数降序，再按枚举值排序，确保同分显示确定。

第六章：协变逆变

6.1 从替换能力理解

假设 Dog 继承 Animal。一个 Dog 可放到需要 Animal 的位置，这是普通引用转换。泛型不自动把这种关系传递到所有容器：List<Dog> 不能赋给 List<Animal>，否则接收方就可能向狗列表添加猫。

协变保留方向：生产 Dog 的来源可当作生产 Animal 的来源。逆变反转方向：能够处理所有 Animal 的处理器，当然能处理 Dog。它们体现“在使用处可安全替换”，不能把里氏替换原则等同于 is/as 类型转换。

6.2 out 协变与 in 逆变

out/in 变体标注仅用于泛型接口和泛型委托的类型参数，不能直接标注泛型类。这不是 ref/out 传参语法。简单记忆：out 主要向外产出 T；in 主要消费 T，复杂嵌套还有更精确的位置规则。

变体转换针对引用类型参数：IEnumerable<int> 不能协变成 IEnumerable<object>，需要逐个投影并装箱。IEnumerable<Dog> 可转换为 IEnumerable<Animal>，即使实际底层对象是 List，也不意味着 List 类型本身变成协变。数组有历史性的引用协变，但向 object[] a = new string[1] 写整数会在运行时抛 ArrayTypeMismatchException。

第七章：多线程

7.1 进程、线程、并发与并行

进程是操作系统管理程序资源与隔离的单位；线程是执行流，同一进程中的线程通常共享托管堆与静态数据，各有调用栈。并发是多个任务交错推进，并行是同时执行。单核也能并发，多线程不保证更快，锁、切换和调度都存在成本。

游戏主线程负责输入、规则和绘制，避免两个线程同时修改棋盘或写控制台。后台线程仅接收落地信息并更新统计，用锁保护队列和结果。

7.2 声明、启动、后台与休眠

前台线程会让进程继续存活；只剩后台线程时进程可结束，后台工作不保证完成。因此后台线程也需明确停止和 Join。Sleep 不释放已持有的 lock，不是可靠的同步协议。Join 不应在持有工作线程需要的锁时调用，否则可能死锁。

7.3 释放：协作退出而非强制销毁

Thread 本身不实现 IDisposable，没有通用的“释放线程”方法。让入口函数返回，线程就结束；之后线程对象由 GC 管理。不要用 Abort 作为退出方案，现代 .NET 不支持它。用取消令牌、停止标记和信号实现退出，最后释放自己创建的同步资源。

真实工作线程还要捕获并报告预期异常，不能让错误静默丢失；不要吞掉所有异常继续运行损坏状态。

7.4 共享数据与同步

counter++ 是读、计算、写，不是单个原子操作。

工具 适用场景 注意
lock 多字段不变量、普通集合读写 所有相关访问使用同一个锁；锁对象私有且稳定
Interlocked 计数、交换等简单原子操作 不能自动保护多步业务事务
volatile 部分字段的可见性与顺序保证 不会使 ++ 或集合操作原子化

不要锁字符串、typeof 或公开的 this，以免外部代码使用相同锁。避免持锁调用未知事件处理器，减少重入和死锁风险。集合的“安全遍历”可先在锁内复制快照，再在锁外排序和显示。游戏统计线程采用这条规则，结束时先停止接收、清空队列、Join，再读取最终结果。

第八章：预处理指令

预处理指令影响编译器如何处理源码，并非运行期分支。C# 没有 C/C++ 式文本宏替换，#define 只定义符号，不保存任意数字值。指令通常单独占一行，无分号。

指令 作用 场景
#define / #undef 定义、取消当前文件条件符号 必须位于普通代码之前
#if / #elif / #else / #endif 条件编译 DEBUG、平台或自定义符号
#region / #endregion 编辑器折叠区域 不改变执行结果
#warning / #error 编译警告、编译错误 配置检查
#nullable enable/disable/restore 控制可空分析上下文 新旧代码迁移
#pragma warning disable/restore 控制指定编译警告 应限制作用范围
#line 调整报告的源码位置 生成代码
#pragma checksum 提供源码校验信息 调试和生成工具

项目级定义可写在 csproj 的 <DefineConstants>$(DefineConstants);GAME_TRACE</DefineConstants>。DEBUG 通常由 Debug 配置提供，不能仅靠“正在调试”判断符号是否存在。运行 dotnet build -c Release 可检查另一条分支。被排除的分支不会生成对应 IL，应对重要配置分别编译验证。

#if 与 [Conditional("DEBUG")] 不同：前者排除代码，后者主要控制调用点是否保留，该方法通常仍存在于程序集。#nullable 不会在运行时自动阻止 null，也不改变对象布局。

第九章：反射和特性

9.1 程序集、元数据与反射

程序集是 .NET 可部署、可版本化的构建单元，常见为托管 dll；其中包含清单、类型和成员元数据，以及通常的 IL 方法体。命名空间是逻辑命名组织，不等于程序集，也不等于文件夹。原生 DLL 不一定是 .NET 程序集，不能一律用 Assembly.Load 加载。

元数据描述“有哪些类型、成员、参数和标记”。反射在运行时读取这些描述，也可构造对象、读写成员、调用方法。用途包括编辑器检查器、序列化、测试发现、插件注册；代价包括运行时错误、查找开销、裁剪/AOT 兼容问题。固定依赖应优先直接调用或接口，反射适合启动阶段发现，结果缓存后使用。

9.5 特性：附加元数据

特性是继承 Attribute 的类。把 [标记(...)] 写在声明上会记录元数据；标记本身通常不会“自动运行规则”，必须由编译器、运行时、框架或你的反射代码读取和解释。

名称末尾 Attribute 在使用时可省略。构造参数是位置参数；可写公共属性/字段可作为命名参数。参数类型受限制，常见为基本数值类型、bool、char、string、Type、枚举和符合规则的一维数组，不能随意传 DateTime、decimal 或业务对象。AttributeUsage 控制合法目标、是否允许多次、是否继承。

GetCustomAttribute 会实例化特性；仅检查元数据而不执行特性构造，可使用 CustomAttributeData。游戏在方块定义类上标记 PieceAttribute，再过滤接口实现并用 Activator 创建，最后存入 Dictionary。

9.6 系统自带特性

Obsolete：过时 API

false 触发编译警告，true 通常阻止调用代码编译；不会自动转发到新方法。应提供替代方式和迁移说明。

调用者信息

放在有默认值的参数上，调用者省略该实参时由编译器填入。CallerArgumentExpression 可获得实参表达式文本；不是运行时扫描调用栈。源码路径可能含构建机信息，生产日志应按需处理。

方法需返回 void；调用点没有 DEBUG 符号时，调用及参数求值通常都被省略。因此不要把重要副作用放在日志参数里。该方法仍可出现在程序集，也不能用它代替权限检查。特性声明在被调用方法上，但是否保留调用由调用方的编译符号决定。

第十章：迭代器

10.1 可枚举对象与枚举器

IEnumerable<T> 表示“能提供枚举器”；IEnumerator<T> 表示“一次遍历的当前位置状态”。集合可被多次遍历，每次 GetEnumerator 通常创建独立枚举器。

foreach 的概念过程：取得枚举器；反复 MoveNext；成功后读 Current；最后 Dispose。首次 MoveNext 前没有有效当前项，结束后也没有有效当前项。

第十一章：特殊语法

11.1 var 隐式局部类型

var 不是 dynamic，类型推断后不变，不能随后把 count 赋成字符串。局部变量需要能推断类型的初始化表达式；var x = null 不行。它不是成员字段、普通方法参数或返回类型的通用替代。

11.2 对象与集合初始值

先执行构造，再赋初始属性/字段；访问限制依然生效。集合初始值通常依赖 IEnumerable 和可用 Add 方法；字典 Add 形式遇重复键抛异常，索引形式可覆盖前值；同一个初始值列表不要混合这两种形式。C# 12 集合表达式 int[] a = [1,2,3] 属于另一种语法，不应与传统 { ... } 初始值混为一谈。

11.3 匿名类型

编译器生成带只读属性的引用类型，适合方法内临时投影。同一程序集、属性名/顺序/类型相同的匿名类型可共享生成类型。不是动态对象，不适合充当稳定公共 API；需要跨模块传递时定义有名类或 record。属性只读不代表其引用对象深度不可变。

11.4 可空类型、空条件、空合并

Nullable 仅用于非可空值类型；Value 在没有值时抛异常。?? 在左侧非 null 时返回左侧，否则求值右侧；??= 仅当左侧为 null 时赋值。?. 遇 null 短路访问链，值类型结果通常提升为可空。空合并不是“空字符串合并”，"" ?? "默认" 仍得到空字符串。后缀 ! 只影响编译器分析，不是运行期 null 检查。

11.5 内插字符串与简写

数值格式可能受区域设置影响，保存机器数据时可明确使用 InvariantCulture。三元表达式适合简单二选一，深层嵌套会降低可读性。

表达式体成员：public int Double(int x) => x * 2;。它是成员语法，不是 lambda 委托。单条 if/for/while 可省大括号，但嵌套时 else 绑定最近未匹配 if，教学和维护建议保留括号。

switch 表达式必须产出值，_ 常作兜底。逻辑简写应保持语义：bool 结果通常直接 return score > 0;，不必再写 ? true : false。简写不是目标，清楚地表达规则才是。

第十二章：值类型和引用类型二

12.1 如何判断

值类型：基本数值、bool、char、enum、struct、值元组、Nullable。引用类型：class、string、数组、delegate、interface 变量所持有的对象引用。接口本身不是某种固定值布局，值类型转接口通常装箱。

运行时可用 typeof(T).IsValueType 或对象 GetType().IsValueType；后者若来自装箱 int，仍返回 true，因为描述的是被装箱的实际类型。null 没有可调用的 GetType。

判断核心在赋值复制语义，不在“栈还是堆”：值类型变量复制其值，引用类型变量复制引用。值类型也可内嵌于堆对象、数组或被装箱；局部变量也可能被闭包提升，JIT 还可把值放寄存器。

12.2 语句块、作用域和生命周期

作用域是源码中可以按名称访问变量的区域；生命周期是运行时存储/对象持续存在的时间。两者不是同一件事。

局部变量在使用前需明确赋值，字段/数组元素通常有默认值。代码块结束不等于对象立即回收；对象无强引用可达后才有资格被 GC 回收，回收时刻不确定。using/Dispose 用于确定性释放资源，不是直接销毁所有托管对象。静态字段通常随加载上下文/进程存活，可能长期保持对象可达。

12.3 结构体中的值和引用

复制结构体会逐字段复制，引用字段只复制引用，不会深拷贝对象。default(Bag) 中 Items 为 null，即使字段被声明为非可空引用，也要考虑结构体默认初始化。可使用不可变结构体和构造验证降低风险。

12.4 类中的值和引用

类对象里可同时有值字段与引用字段；赋值类变量只复制类对象引用，因此通过两个变量看到的是同一份字段。

MemberwiseClone() 创建浅复制：新外层对象有独立值字段，但引用字段仍共享目标。深复制需要按业务关系处理整个对象图，尤其要考虑循环和共享关系，不能简单写个通用递归就认为正确。

12.5 数组中的存储规则

数组 槽位内容 新建后默认内容 Clone 结果
int[] int 值 0 独立整数槽位
Bag[] Bag 值，含其引用字段 Gold=0、Items=null 结构体复制，Items 仍可能共享
Wallet[] Wallet 引用 null 新数组仍引用相同 Wallet
int[][] 每行 int[] 的引用 null Clone 只复制外层行引用

数组本身始终是引用类型。new Wallet[3] 只创建三个引用槽位，没有创建三个 Wallet。对 List 索引器返回的结构体不能直接改字段：先取出局部副本，修改后写回；数组元素变量的规则不同，可直接修改其结构体字段。结构体属性返回值也容易出现“改了副本”的问题。

12.6 结构体实现接口与装箱

结构体可实现接口，但不能继承自定义类或另一个结构体；它隐式继承 System.ValueType。泛型约束调用通常可避免转换成接口导致的装箱；这里使用 ref 还保证修改原结构体，而不是参数副本。并非所有泛型代码永远不装箱，应根据具体转换和调用分析。

第十三章：项目实践——俄罗斯方块

13.1 项目目标与规则

本项目把前面教程的控制台、数组、循环、结构体、接口、封装继承多态，与本教程的泛型、事件、线程、反射和迭代器连起来。先读规则，再读模型，再读主循环，不要从绘制细节开始。

  • 固定棋盘为 10 列 × 20 行，七种四格方块 I/O/T/S/Z/J/L。
  • 七袋随机：每袋恰有七种方块各一个，用 Fisher–Yates 洗牌后顺序出队。
  • 方块自动下落，左右移动、顺时针旋转、软降、硬降。下落失败立即锁定。
  • 一行全部填满时删除，上方行向下压缩；一次可消 1～4 行。
  • 新方块出生即发生碰撞时结束；开始、游戏、结束分别由场景类管理。
  • 软降每成功移动一格 +1，硬降每格 +2；消 1/2/3/4 行基础分为 100/300/500/800，再乘消行前等级。
  • 每累计 10 行升一级；下落间隔从 600ms 起每级减 45ms，最短 80ms。
  • P 暂停，Esc 回菜单，结束后 R 重开，Enter 回菜单，Esc 退出。

旋转是教学简化规则：在 4×4 模板内旋转，O 不变，依次试水平偏移 0、-1、+1、-2、+2；没有完整 SRS、向上踢墙、隐藏出生行、锁定延迟、Hold、T-Spin 或连击规则。读者应将其视为完整可玩的教学版本，而非竞技规则复刻。

界面 72 列 × 32 行，上方约四分之三为棋盘、下一块预览与状态，下方为最近五条落地/消行日志。游戏没有战斗，因此日志记录消行和操作反馈。活动方块显示 []，固定方块显示字母；边框始终绘制。窗口过小时暂停更新并显示尺寸提示，恢复后不会追赶整段停顿时间。

13.3 坐标与数据模型

坐标原点在棋盘左上，x 向右，y 向下。cells[y,x] 的第一维是行，与索引器 board[x,y] 参数顺序不同，必须明确。空格用 TetrominoKind? 的 null 表示；enum 的 0 是 I，不应拿 0 当空格。

GridPoint 是只读结构体，提供值相等、GetHashCode、加法和 ==，可用于 HashSet 去重。Board 内部二维数组不向外暴露，渲染层只能通过 IGameView 取得只读状态和枚举序列。

活动方块由 PieceDescriptor、Position、Rotation 组成。移动和旋转先产生候选对象，通过碰撞检查后才替换 active，失败时原方块保持原状。这是“先验证，再提交”的小型状态更新方式，避免移动一半才发现重叠。

旋转公式是 (x,y) → (3-y,x)。四次旋转应回到原始格子集合；O 特判不变。这个公式围绕模板中心旋转，故 I、J 等的视觉位置会与完整 SRS 不同。

13.4 碰撞、下落与锁定

Board.CanPlace 对四个格子逐个检查边界和是否被占据，必须先判断边界，再读取数组，利用短路避免越界。

DropOne 尝试向下移动，成功可奖励软降分；失败调用 LockActive。HardDrop 反复 TryMove 到最后合法位置，再统一锁定一次。结束后所有移动返回或无效果，避免重复落地、重复加分。

LockActive 的顺序是：写入棋盘 → 消行 → 按旧等级计算奖励 → 更新行数和分数 → 生成下一块并检查结束 → 发布落地事件。事件处理器能观察到完整的新状态；外部事件处理器不应直接改动引擎内部状态。

13.5 消行压缩算法

使用 readRow 与 writeRow 从底部向上扫描：满行跳过，不满行复制到 writeRow，再让 writeRow 上移。最后把顶部剩余行清空。单次消行成本 O(行数×列数)，不需要反复移动整个棋盘。

这段解释版省略 cleared 计数，源码保留完整返回值。连续满行和中间隔着非满行都应正确；从上往下逐行删除容易漏行，因此配套检查覆盖所有四行满/不满组合。

13.6 主循环与场景生命周期

主循环每轮：检查窗口 → 读取有限数量按键 → 计算经过时间 → 更新场景 → 绘制 → 小幅休眠。时间用 Stopwatch，不能用“每循环一次就下移一格”，否则不同机器速度不同。

场景有 Enter、Handle、Update、Render、Exit。开始场景只处理开始/退出；游戏场景控制暂停和落地日志；结束场景展示得分、行数、方块排名。切换时旧场景先 Exit，新场景再 Enter，订阅和清理均有对称位置。

PlayScene 累积时间，达到 FallMilliseconds 就 Tick；暂停时不积累时间，恢复时不瞬间下落多格。硬降后重置下落计时，避免新方块刚生成就吃掉旧方块剩余的时间。

13.7 事件与统计线程

PieceLockedEventArgs 仅保存枚举和整数，只读属性使数据交给后台后不再变化。StatisticsWorker 在 lock 内入队并发信号；后台从队列取出事件，用 Dictionary 更新计数；Capture 在锁内复制快照。

AutoResetEvent 的信号可能合并，所以它只表示“可能有工作”，事件本身必须留在 Queue 中。消费者醒来后持续处理，队空才再等待。不能把信号次数当成事件次数。

退出顺序：取消游戏事件订阅 → 标记 stopping 并发信号 → 不持锁 Join → 工作线程处理完已入队事件后返回 → 释放信号。结束场景读取 Join 之后的快照，保证最终计数不落后。正常游戏帧里的统计可能短暂落后于画面，这是异步统计的预期表现。

13.8 反射注册方块

每个方块定义实现 IPieceDefinition，并标记 [Piece(TetrominoKind.T,"T")]。启动时扫描明确指定的自身程序集，过滤非抽象类和接口实现，再读取特性、检查公开无参构造、Activator.CreateInstance，最后建立字典。

这是本教程的“泛型 + 约束 + 反射 + 特性”的组合案例：CreateAll<TContract,TAttribute> 用 class 和 Attribute 约束保证基本能力；IsAssignableFrom 进行运行时筛选；注册完成后正常游戏走接口和缓存，不每帧反射。

新增方块还需同步枚举与规则假设；代码仅保证七种标准方块，并不承诺“随便增加任意形状就完全兼容”。结构扩展需要一并检查随机袋、棋盘、计分与渲染范围。

13.10 自测流程与项目局限

先按 Enter 开始，左右移动至边界并旋转；按 P 后观察方块停住，等待几秒再恢复；按 Space 多次堆叠到出生区触发结束；按 R 确认分数、棋盘和统计都重置；Esc 回菜单再退出。缩小终端后应出现提示，调大后继续。

自动检查用固定随机种子覆盖七袋预览与出队、四次旋转、边界、棋盘复制隔离、消行顺序、精确计分、出生碰撞、游戏结束后无额外操作、暂停及统计清空。随机模拟用于发现状态不变量问题，不能替代所有人工可玩性评估。

Console API 在不同终端上的按键重复速度与刷新效果可能不同；动态调整窗口恰逢绘制时程序会提示重新启动。反射扫描依赖元数据，本文未启用裁剪或 Native AOT；若以后启用，需为反射目标显式保留元数据或改为生成注册表。

练习与参考答案

章节 练习 参考答案要点
1 为什么不能把装箱 int 直接拆成 long？ 拆箱必须匹配盒中值类型，先拆 int 再数值转换
2 编写能创建对象且调用 Id 的工厂 where T : IHasId, new()；接口提供 Id，new() 提供构造能力
3 删除单链表最后一个节点要更新什么？ 前驱 Next=null、tail=前驱；唯一节点时 head/tail 均 null；Count/version 更新
4 为什么事件处理器要取消订阅？ 发布者可能持有订阅者引用，导致生命周期延长或旧场景重复响应
5 给同分玩家一个确定顺序 比分数，再用姓名或唯一 id；不用减法比较整数
6 为什么 List 不能给 List？ Animal 列表允许加 Cat，会破坏 Dog 列表类型安全；只读生产接口可协变
7 为什么 Sleep 不能保证工作已完成？ 调度时间不确定，也没有完成状态或内存同步协议；用 Join/信号/Task
8 Release 中被 Conditional 省略的日志参数会执行吗？ 未保留调用时通常不会，因此不能依赖参数副作用
9 特性为何不会自动调用业务代码？ 它通常只保存元数据，需要消费者读取解释
10 yield 方法中的异常为什么可能晚发生？ 方法体通过状态机在 MoveNext 时执行；可拆验证与迭代主体
11 var 与 dynamic 的区别？ var 编译期静态推断，dynamic 把部分绑定延迟到运行时
12 复制含 List 字段的结构体为何会共享内容？ 结构体字段复制，List 字段复制的是引用
项目 为什么需要在 Join 后读取结束统计？ 后台可能尚未消费完队列，Join 确认退出并完成积压工作

建议扩展：增加按键设置、最高分持久化、幽灵落点、完整 SRS、Hold。每次只新增一项规则，并先为状态边界写检查。若新增存档线程，继续保持棋盘由主线程独占，把不可变快照交给后台。

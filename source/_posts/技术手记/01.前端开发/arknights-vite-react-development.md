## 一、网站要解决什么问题

剧情资料分散在主线、SideStory、故事集、密录及其他模式中。阅读者可能记得人物或地点，却不知道该从哪篇故事开始；按活动上线时间浏览，也不能直接等同于故事发生顺序。

首版围绕三条路径组织内容：

1. **从时间出发**：选择泰拉整理定位或国服实装顺序，找到故事并进入独立播放器。
2. **从人物或地点出发**：通过搜索、干员列表、组织关联、地区地图进入资料，再回到剧情。
3. **从世界观出发**：先阅读源石、天灾、科技、种族、国家与组织的基础导读，再进入相关故事。

首页、总览、设定、其他是四个主页面；播放器、图谱、地图和干员档案是独立视图。这里的“独立页面”指可分享的应用内地址，点击后沿当前标签页阅读，不强制打开大量新标签。

## 二、本版内容清单与限制

资料截止 **2026年10月25日**，本次版本与字段核对日期为 **2026年10月26日**。它是一份资料快照，没有游戏更新后自动追更的机制。

| 内容 | 实际规模 | 阅读时如何理解 |
|---|---|---|
| 叙事单元 | 688 | 含主线、SideStory、短篇、密录、模式结局等，并非688场大型活动 |
| 原创梳理场景 | 1558 | 73篇含943个扩展节点；其余615条各提供一段概要 |
| 泰拉编年 | 261项整理定位、427项未定 | 含推定与特殊世界线，不逐项等同官方明确日期 |
| 干员索引 | 432条列表记录、434个形态、394个人物身份 | 异格与职业形态不能都当成不同人物计算 |
| 设定 | 6章、44个导读入口 | 原创基础导读，不是《大地巡旅》全书内容 |
| 地区 | 24项，其中23项有概略标点 | 杜林保留目录入口；没有编造精确坐标与国界 |
| 关系图谱 | 4组、27条组织或剧情关联 | 不是完整人物亲属网，也没有逐年身份复原 |
| 图片 | 28张精选CG、首页背景、部分头像与人物图等 | 配图和人物为关联示意，不是逐节点原始舞台 |

干员事实字段中有380项种族、378项出身地信息，未知及未公开信息保持空值，不补猜测。只有8张头像保存在项目内，其余按需请求公开图片资料库，失败时显示占位。相关剧情由现有梳理中的姓名检索得到，不代表完整出场统计。

主播放器没有逐节点原始BGM、音效或配音；塞壬唱片区域提供官方收听入口。本版也没有云端账号、跨设备同步或后台编辑器。

## 三、四个主页面的功能需求

### 1. 首页：巴别塔到罗德岛

顶部参考明日方舟官网的导航构图：左侧Logo，右侧英文标题在上、中文标签在下，当前页面通过青色线条亮起。页面保留“非官方剧情档案”的身份说明。

开场顺序为巴别塔标志渐显、镜面碎片离场、罗德岛标志揭示、Logo与中英文标题组成横向锁定组合，最后露出向下入口。碎裂使用CSS裁切与变换演绎，未直接复刻游戏原始动画。

交互要求是可跳过、可重播、同一会话不反复打断阅读；开启减少动态效果时直接显示首页。向下按钮和首页向下滚轮进入总览，浏览器缩放手势不应被当作翻页。手机使用按钮即可进入，不依赖滚轮。

### 2. 总览：事件轨道与三个入口

上半部用图片、名称、时间、类型和短概述展示当前故事；下方为横向事件轨道。滑块、左右按钮、方向键、上半区滚轮以及触屏横滑联动切换选中故事。选中位置保存在本机，返回总览时能够恢复。

时间维度有两种：**泰拉时间**按已有整理定位排序，**实装顺序**按国服上线日期排序。未定年代排到已知定位之后，页面保留“未定”与世界线标识。当前轨道按事件压缩间距，明确标注“时间间隔已压缩”，不能根据两张卡片的视觉距离推算相差几年。

默认聚焦主线、SideStory与故事集总览，也能切换全部688条档案或按类型筛选。新读者默认折叠未读简介，主动展开只展示当前故事；完整档案模式会展开更多内容。

总览下方连接关系图谱、时空地图、干员档案。全站搜索和全部剧情目录提供另一条快速入口，不必在时间轴上逐个滚动查找。

塞壬唱片入口引导到官方站收听。图集支持主线/活动分类、分批载入、点击大图、上一张/下一张、来源和剧情回链。新读者模式默认模糊图集缩略图，点击当前图片才展开，减少未读剧情的直接画面暴露。

## 四、独立剧情播放器需求

播放器参考PRTS剧情阅读页的“演出区域＋对话框＋播放控制＋记录”结构。实际界面由React渲染，当前素材与文本类型在页面中直接说明。

| 操作 | 本版行为 |
|---|---|
| 开始阅读 | 从保存的游标进入，也能从头开始 |
| 点击/空格 | 文字未显示完时补全；再次操作进入下一句或场景 |
| AUTO | 当前句完成后按阅读时长推进，打开弹窗、日志或切到后台时暂停 |
| LOG | 仅列出已经完整显示的梳理句子，可点回相应节点 |
| LOG ALL | 展示当前场景的全部梳理文字，不直接展开后续场景 |
| SKIP | 进入下一梳理场景；不是自动读完整篇 |
| HIDE | 暂时隐藏对话框，保留配图阅读空间 |
| 章节目录 | 桌面侧栏，手机抽屉；按原章节顺序跳转 |
| 全屏 | 由用户点击触发；浏览器不支持时给出反馈 |
| 原文与来源 | 提供篇章入口、脚本来源及当前节点行动前/后的链接 |

播放器将**场景序号**与**句子序号**分别保存。假设读者在场景A读到第2句，之后打开明确指向场景B的链接，不能把A的行号直接套到B；恢复函数会重新校验有效范围。直接刷新相同场景则恢复对应行号。

逐字显示状态也绑定场景与行号，避免新句沿用上一句的完成状态而提前写入已读记录。逐字计时器与自动推进计时器分别清理，离开页面不会继续在后台推进故事。回忆仍按原章节结构阅读，不因其发生年代较早就从当前剧情中抽离。

记录使用`localStorage`，键为`terra-progress-v1`，包含`scene`、`line`、`seen`、`finished`和`updated`。阅读设置也在本机保存，可导出记录为JSON。本版没有导入与云端同步；清理浏览器数据或更换设备不会自动恢复记录。

## 五、图谱、地图和干员档案

关系图谱首版选择罗德岛、企鹅物流、喀兰贸易、莱茵生命四组。中心组织连接关联人物，点击节点出现资料侧栏，再进入干员档案。连线表示组织或剧情关联，不代表所有时期的直接雇佣状态；部分中心图标为通用示意，不能当成各组织完整正式标识。

地图使用实际游戏泰拉底图，叠加人工整理的概略导航点。支持平移、缩放、复位、现代国家/历史政体/海域/城市等图层及地区目录。国家详情包含基础介绍、已知地点和剧情回链。未来要加入历史国界或精确城市位置，需要单独提供可核对的证据。

干员列表按姓名、英文名、职业、所属地区和种族组合筛选，逐批加载卡片。人物详情包含来源、基础事实、形态关联和相关剧情。人物身份通过`char_meta_table.spCharGroups`关联本体与异格，阿米娅职业形态参考`char_patch_table.infos`。数据中保留游戏形态ID与人物身份ID，避免把同一人物的不同形态混为互不相关的记录。

## 六、为什么采用这个技术结构

项目由Vite官方React脚手架创建：

~~~bash
npm create vite@9.3.1 projects/arknights -- --template react --no-interactive
~~~

脚手架版本为9.3.1，锁定安装中的React为19.3.1、Vite构建工具为8.3.5。最低Node.js版本为22.12，仓库的GitHub Actions继续使用Node.js 22。确切依赖以`package-lock.json`为准，不把脚手架版本误写成Vite运行版本。

网站是静态资料站，首版的阅读状态可以保存在本机，因此不需要服务端账号或数据库。React负责组件和交互状态，Vite负责开发服务、模块打包和按页分包，GitHub Pages负责托管构建结果。博客仍由Hexo与Fluid生成。

| 文件 | 职责 |
|---|---|
| `src/App.jsx` | 资料加载、hash路由、按页加载、错误边界 |
| `src/context.jsx` | 资料、偏好、阅读记录、弹窗与提示 |
| `src/components/Shell.jsx` | 导航、页脚与正文焦点入口 |
| `src/components/Modals.jsx` | 搜索、设置、来源、词条目录和图集大图 |
| `src/pages/Overview.jsx` | 排序、筛选、时间轨道及故事卡片 |
| `src/pages/Player.jsx` | 游标、逐字显示、自动推进、记录、目录与全屏 |
| `src/pages/Explore.jsx` | 地图视口与组织关联图 |
| `src/pages/Archive.jsx` | 剧情目录、干员筛选和人物详情 |
| `src/pages/World.jsx`、`More.jsx`、`Home.jsx` | 设定、图集和首页转场 |
| `src/lib/archive.js` | 排序、恢复游标、链接检查及资料加载 |
| `scripts/validate-data.mjs` | 数据与本地资源一致性校验 |

`React.lazy`与`Suspense`让播放器、地图等页面在进入时按需加载。共享状态放在Context，页面内部的选中项、展开状态与地图视口由对应组件管理。副作用使用`useEffect`清理，开发时保留`StrictMode`检查重复装卸下的行为。

所有剧情文本作为React文本节点显示，外部来源链接仅接受HTTP/HTTPS；没有把来源文字直接作为HTML注入页面。图片请求失败有占位，本机存储不可用时仍能阅读。构建时输出gzip剧情副本，浏览器支持时优先解压读取，失败或旧环境回退普通JSON。

## 七、数据模型与维护约定

| 实体 | 当前关键字段 |
|---|---|
| 故事 | `id/gameId/name/type/series/seriesLabel`、`time/year/timeLabel/release/continuity`、`sources/scenes` |
| 梳理场景 | `id/title/text/source/textMode/isOriginalSynopsis`、可选背景与原始片段入口 |
| 干员形态 | `id/personId/formIds`、姓名、职业、星级、阵营、种族、出身地、图片与来源 |
| 地区 | `id/name/en/type`、介绍、地点、关键词、来源、可为空的概略坐标 |
| 本机记录 | 故事ID对应的场景、句子、已读集合、结束标记与更新时间 |

`id`应保持稳定。更新资料时不应因为插入一个节点就给后续所有旧节点重编号，否则旧收藏和阅读进度会错位。新增图片要在`public/assets/sources.json`中记录来源及对应剧情。

编辑`public/data/archive.json`后，需要重新生成同内容的`archive.json.gz`，再执行构建校验。校验会检查计数、重复ID、原创梳理标记、形态链接、本地资源路径及gzip一致性。**程序校验通过不等于剧情事实与年代已经被官方确认**，内容修订仍要对照原始来源。

## 八、本地开发与GitHub自动发布

独立开发React站：

~~~bash
cd projects/arknights
npm ci
npm run dev
~~~

开发服务地址以终端输出为准。生产检查使用：

~~~bash
npm test
npm run build
npm run preview
~~~

整个仓库采用“源码项目＋生成目录”的结构：`projects/arknights/`存完整源码；Vite输出`projects/arknights/dist/`；工具将成品复制到`source/arknights/`；Hexo最终输出到根`public/`。三个生成目录均不作为开发源文件维护。

在仓库根目录运行`npm ci`、`npm run build`，流程为：

1. 根`prebuild`确保Fluid子模块可用，再按子项目锁文件安装React站依赖。
2. `tooling/build-arknights.mjs`执行子项目测试与Vite构建，再复制到`source/arknights/`。
3. Hexo清理并生成整个博客。`_config.yml`增加`arknights/**`到`skip_render`，让React入口保持原样。
4. 现有`.github/workflows/deploy.yml`在`main`提交后发布整个`public/`到`gh-pages`，由Pages托管。

这样无需再建立一条互相覆盖的Pages工作流，也不用把构建产物手工复制进发布分支。后续只要修改源码或资料并提交到`main`，现有流程就会重新构建网站和博客。

Vite配置`base:'./'`，构建资源可以在`/arknights/`子路径加载；剧情地址采用`#/story/故事ID/场景序号`，直接刷新不需要GitHub Pages提供服务端路由重写。开发环境与公开网址属于不同origin，各自的本机记录也相互独立。

## 九、验收依据与当前测试范围

本版的逻辑测试覆盖未知年代与实装排序、旧进度与直接链接冲突、越界游标、外部URL协议以及中文断句。生产构建前另做数据校验，并验证React成品能随Hexo一起生成。

浏览器检查覆盖首页、时间排序切换、搜索进入剧情、开始阅读、LOG ALL、下一段、刷新续读、AUTO开关、当前行动前/后来源、地图与设定跳转、干员形态、图谱侧栏和图集弹窗。390×844内嵌视口用于检查小屏时间轴、移动导航和播放器章节抽屉。

这些检查不等于所有设备的完整兼容认证。真实触屏手势、Safari、辅助技术、所有外链头像以及动画逐帧效果仍需进一步验证。公开发布结果应以GitHub Actions日志与实际页面为准。

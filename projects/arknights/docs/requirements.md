# 泰拉剧情档案：功能与开发需求规格 v0.1

版本日期：2026-10-26。技术约束：Vite 官方 React 脚手架、静态部署、GitHub 源码与 GitHub Pages、与现有 Hexo 博客共存。

## 1. 目标与内容边界

面向希望按时间、人物或地区阅读明日方舟剧情的读者。核心路径为“首页 → 时间轴 → 阅读剧情 → 返回原位置”，另可从角色、组织、国家与设定回到关联剧情。

当前版本是可运行的剧情资料导航与**原创梳理阅读站**，不是原作完整脚本库。界面展示实际收录量与截止日期，保留原文入口。未来接入完整脚本时，必须逐项记录文本版本、来源与资源对应，不能把概要拆成句子后标成原作逐句演出。

## 2. 信息架构

| 导航 | 地址 | 页面责任 |
|---|---|---|
| INDEX 首页 | `#/home` | 巴别塔转场、罗德岛标题与总览入口 |
| OVERVIEW 总览 | `#/overview` | 时间轴、剧情卡片、图谱/地图/干员入口 |
| WORLD 设定 | `#/world/:chapter/:topic` | 六章目录与词条导读 |
| MORE 其他 | `#/more` | 塞壬官方入口、精选CG图集 |
| 剧情目录 | `#/stories` | 分类、查询和逐批载入 |
| 独立播放器 | `#/story/:id/:scene?` | 按章节顺序阅读并保存进度 |
| 关系图谱 | `#/relations/:group?` | 组织视角的关联概览 |
| 时空地图 | `#/map/:country?` | 地区检索、标记与详情 |
| 干员列表/详情 | `#/operators`、`#/operator/:id` | 筛选、事实字段、形态链接与剧情回链 |

路由是同一 React 应用内的独立视图，不为每个故事打开浏览器新标签。hash 地址可以收藏、分享和刷新；静态服务器只需要返回入口文件。

## 3. P0 功能及验收

P0 为本版实现范围；P1、P2 是后续开发目标，不混写为完成项。

| 编号 | 功能要求 | 验收方式 |
|---|---|---|
| NAV-01 | 左侧明日方舟Logo，右侧英文上、中文下；当前主页面亮起 | 每个主入口均可达；子页面归属总览；小屏有展开按钮 |
| HOME-01 | 巴别塔渐显、镜面碎片、罗德岛揭示、横向标题组合、浮动箭头 | 首次会话播放；可跳过及重播；减少动态效果时直接显示结果 |
| HOME-02 | 箭头与向下滚轮进入总览 | 原生页面缩放手势不拦截；触屏有按钮可替代滚轮 |
| TL-01 | 横向事件轨道，支持泰拉定位/实装顺序与类型筛选 | 滑块、上下条按钮、左右键、上半区滚轮和触屏滑动同步切换故事 |
| TL-02 | 卡片显示图片、标题、简述、时间、类型、世界线与来源 | 未定日期不伪装精确年代；轨道注明“时间间隔已压缩” |
| TL-03 | 选择位置本机保存；未读简介默认折叠 | 返回总览恢复选择；只展开主动选中的简介 |
| READ-01 | 点击阅读进入独立播放器 | 地址含稳定故事ID；直接刷新可继续进入正确故事 |
| READ-02 | 逐字显示，点击/空格补全并推进，AUTO、SKIP、HIDE | AUTO等待当前句完成后推进；SKIP到下一梳理场景；切页与切后台清理/暂停计时器 |
| READ-03 | LOG只显示已完整显示的句子；LOG ALL仅显示当前场景全文 | 查看日志不直接暴露后续场景；可从记录返回对应节点 |
| READ-04 | 章节目录、上一/下一段、全屏、恢复进度 | URL显式指定其他场景时不套用旧场景行号；非法游标被限制在有效范围 |
| READ-05 | 剧情梳理标识、精选配图说明、原文与当前行动前/后入口 | 不暗示图片、人物或音轨是逐节点原始对应；无音轨状态清晰 |
| GRAPH-01 | 4个组织切换，人物节点点击后显示资料侧栏 | 可进入干员详情；组织关联与亲属关系有明确区分 |
| MAP-01 | 实际游戏底图、概略标点、图层、平移缩放和复位 | 23个标记可达；杜林在地区目录中可达；位置不称为官方精确坐标 |
| MAP-02 | 选国家显示介绍、已知地点与关联剧情 | 可跳到对应设定条目，并返回地图；国家选择可收藏 |
| OP-01 | 中文/英文名、职业、所属地区、种族筛选，图片失败回退 | 条件可组合，空状态可清空；逐批载入，避免同时请求全部头像 |
| OP-02 | 本体、异格和阿米娅职业形态关联 | 通过事实映射连接同一人物；新读者可主动展开形态关系 |
| WORLD-01 | 六章侧栏、词条切换、来源和剧情回链 | 覆盖源石/天灾/矿石病、科技、生物、种族、国家地区、组织 |
| MORE-01 | 塞壬官方收听入口和CG分类图集 | 图集点击放大、切换前后张、显示来源并回到剧情 |
| SYS-01 | 全站搜索、阅读设置、来源弹窗、本机记录导出 | 搜索覆盖故事、干员、地区、设定；无结果有说明；Esc关闭弹窗 |

## 4. 视觉与适配

采用深色灰阶、青色当前状态、窄体英文、细分隔线和档案编号。Logo、CG、地图保留来源；使用真实素材时注明其所属。长篇设定正文采用浅色底提高阅读性。首页动画为CSS碎片演绎，不声称与游戏原始动画像素一致。

桌面保持横向导航、时间轴上部双栏、下方三入口；约800px以下折叠播放器侧栏；约600px以下使用移动导航、上下排列的剧情卡与独立目录抽屉。正文、控件和图片不得因长标题造成整页横向溢出。屏幕阅读器应能识别按钮名称、页面主标题、表单标签和播放状态；提供焦点轮廓、跳到正文及减少动态效果设置。

当前小屏验收采用390×844的浏览器内嵌预览；不将它等同于所有手机、Safari及辅助技术的完整兼容认证。

## 5. 当前数据契约

- 故事：`id`为本站稳定ID，`gameId`为游戏标识；`name`、`type`、`series`、`seriesLabel`；`time`、`year`为可为空的排序定位，`timeLabel`保留文字范围；`release`为国服实装日；`continuity`保留世界线；`sources`与`scenes`不可缺失。
- 梳理场景：`id`、`title`、`text`、`source`、`textMode`、`isOriginalSynopsis`；`segments`可存原始行动前/后链接；`background`是可选精选配图。
- 人物：游戏形态`id`、人物身份`personId`、关联`formIds`；姓名、英文名、职业、星级、阵营、种族、出身地、图片和来源。未知字段使用null，不补猜测内容。
- 地理：`id/name/en/type`、介绍、已知地点、关键词、来源，`x/y`为归一化概略导航坐标；无可靠位置为null。
- 阅读进度：以故事ID保存`scene/line/seen/finished/updated`；只保存在本机浏览器，版本键为`terra-progress-v1`。

本次迁移保留原有数据ID与本机存储键。开发环境与公开网址属于不同origin，二者的本机进度不会自动互通。

## 6. P1 内容与功能扩展

| 编号 | 后续需求 | 必备数据或验收条件 |
|---|---|---|
| CONTENT-01 | 合法来源的完整剧情脚本与版本管理 | 明确文本版本、来源、可用范围和修订记录；原文与原创梳理分开 |
| PLAYER-01 | 逐节点背景、立绘、表情、音轨与转场 | 定义有序舞台事件与资源ID；缺资源明确回退；静音和浏览器自动播放限制可处理 |
| TIME-01 | 日期区间、可信度、证据与回忆关联 | 增加`from/to/certainty/evidence/flashbackOf`等模型；未定区独立展示 |
| TIME-02 | 多泳道、等比例/压缩比例、缩放 | 在缩放下保持选中事件，区分并发地点与不同世界线 |
| GRAPH-02 | 有效年代、关系类型、逐条证据 | 每条边有来源与有效时间，历史人物身份可按时间切换 |
| MAP-03 | 可核对的更精细地点和历史图层 | 每条地理信息有出处；国界和坐标的可靠性独立标注 |
| UPDATE-01 | 增量资料更新与审校 | 生成变更清单，经人工核对后提交；不可把自动抓取等同于事实确认 |

P2包括云端阅读同步、后台内容编辑和更广泛的浏览器/无障碍验收。它们需要新的服务、数据与账号设计，本版不预留虚假的登录或播放入口。

## 7. 发布与完成标准

源码提交至`projects/arknights/`，需求文档和博客文章一并入库；GitHub Actions使用现有Hexo流程构建并发布。完成需满足：依赖锁存在、单元测试通过、数据校验通过、Vite构建成功、Hexo整站生成成功、公开首页和剧情深层链接能打开、博客文章公开可读。

内容是一次资料快照，不会随着游戏更新自动同步。页面数据量和“已实现”清单必须随内容与代码实际状态更新。
